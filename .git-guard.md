# Git Repository Guard Configuration

This document describes the safeguards installed to prevent repository bloat (312MB+ incidents).

## Problem

A catastrophic commit (a8cd5e45) previously added 321,149 files (112GB+) of decompiled APK output, causing severe repo bloat. This has been removed and prevention measures installed.

## Prevention Strategy

### 1. Pre-commit Hook (`.git/hooks/pre-commit`)

**Checks before each commit:**
- Forbidden directories: `jadx-output/`, `apktool-output/`, `apktool/`, `jadx/`, etc.
- File size limit: 50MB per file
- Binary file warnings for suspicious executables

**Trigger:** `git commit`
**Action:** Blocks commit if any check fails

### 2. Post-commit Hook (`.git/hooks/post-commit`)

**Checks after each commit:**
- Repository size monitoring
- Warning if `.git/` exceeds 300MB

**Trigger:** After successful commit
**Action:** Prints warning (non-blocking)

### 3. Comprehensive .gitignore

**Three categories of exclusions:**
1. **Decompilation outputs** - `jadx-output/`, `apktool/`, etc.
2. **APK artifacts** - `.apk`, `.dex`, `.idsig` files
3. **System files** - `.DS_Store`, `build/`, `.gradle/`, etc.

**Key rules:**
- Only tracked: `.sha256` and `.info` metadata files
- Never tracked: APK binaries (documented by checksum instead)

### 4. Git Configuration

**Run after cloning:**
```bash
# Aggressive garbage collection
git gc --aggressive

# Report large objects
git rev-list --all --objects | sort -k2 | tail -10
```

## Threat Scenarios & Response

### Scenario 1: Accidentally running `git add -A`

**Before:** Would add 100GB+ of decompiled files
**After:** Pre-commit hook blocks with error

### Scenario 2: Decompiling APK in tracked directory

**Before:** All output files added next commit
**After:** Immediately caught by `.gitignore`

### Scenario 3: Repository grows unexpectedly

**Before:** No warning
**After:** Post-commit hook warns if size > 300MB

## Manual Verification

```bash
# Check current repo size
du -sh .git

# Find largest files in history
git rev-list --all --objects | \
  sed 's/^[^ ]* //' | \
  sort -rn | \
  head -20

# List recent commits by size
git log --oneline --all --graph
```

## If Prevention Fails

1. **Stop immediately** - don't push
2. **Identify culprit** - `git show <commit> --stat`
3. **Revert or rebase** - remove commit from history
4. **Run GC** - `git gc --aggressive`
5. **Force push** - `git push --force-with-lease` (if needed)

## Maintenance

- **Weekly:** Run `git gc` to reclaim space
- **Monthly:** Check `du -sh .git` is under 300MB
- **Per-commit:** Verify pre-commit hook is passing
